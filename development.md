# Developing RuneDefence

## Requirements
- JDK 11. Plugins must stay Java 11 compatible.
- Python 3, only for the scripts in `tools/`. They use the standard library, so there's nothing to install.

## Local-only files
`src/test/` and `RuneDefence_Technical_Design.md` are gitignored, so a fresh clone doesn't have them. `./gradlew build` still works without them, but the commands marked below need your own copy of `src/test/`.

`src/test/` also holds the launcher for `./gradlew run`, the standalone dev window and the screenshot renderer, as well as the tests.

## Commands
| Command | What it does | Needs `src/test/` |
| --- | --- | --- |
| `./gradlew build` | Compiles the plugin and builds the jar. | No |
| `./gradlew test` | Runs the engine, progression, UI and balance tests. Without `src/test/` it finds nothing to run. | Yes |
| `./gradlew run` | Launches RuneLite in developer mode with the plugin loaded. | Yes |
| `./gradlew playDev` | Plays the game in a standalone window, with no OSRS client or login. Its buttons add gold and XP. | Yes |
| `./gradlew balanceReport` | Prints how far each level gets. Add `--args=maps` to report per map, or `--args=binders` to compare boards with and without binders, which the bot wouldn't otherwise value. | Yes |
| `./gradlew screenshots` | Renders the panel offscreen into `screenshots/`. This shows the UI and engine only, not the client. | Yes |
| `python3 tools/gen_sprites.py [preview.png]` | Regenerates the sprite sheets, their index and both icons. | No |
| `python3 tools/gen_waves.py` | Rewrites waves after 25 in `content.json` from the tables in the script. Waves 1 to 25 are written by hand. | No |

## Testing in-game
Unit tests and `playDev` don't exercise the RuneLite integration, so check XP tracking, account switching and settings changes in the real client. Use `./gradlew run`, and follow [Using Jagex Accounts](https://github.com/runelite/runelite/wiki/Using-Jagex-Accounts) to log in to the development client.

Never automate game input, including through screen-capture or computer-use tools. It breaks Jagex's third-party client guidelines and can get an account banned.

## Project layout
Everything is under `src/main/java/com/runedefence/`:

| Path | Contents |
| --- | --- |
| `RuneDefencePlugin.java` | Plugin entry point: RuneLite events, account switching and saving. |
| `RuneDefenceConfig.java` | The settings shown in RuneLite. |
| `client/` | `XpProgressTracker`, which decides how much of each XP change counts. |
| `content/` | Loads and validates `content.json`. |
| `engine/` | The game itself. It has no RuneLite dependencies, so it can be tested without a client. |
| `model/` | Game data and saved state. `Progression` turns stored XP into levels. |
| `persistence/` | `SaveRepository`, which reads and writes per-account saves. |
| `ui/` | The sidebar panel and everything drawn in it. |

Game data is in `src/main/resources/com/runedefence/`: `content.json` holds the defenders, enemies, maps and waves, and `sprites/` and `sprites.json` are generated by `gen_sprites.py`.

## Sprite sheets
The Plugin Hub flags any image that's too large once decoded, measured as width × height × 4 bytes, whatever the file size. It publishes no limit, so `gen_sprites.py` refuses to write a sheet over 512 KiB.

| Sheet | Contents |
| --- | --- |
| `map_<id>.png` | Enemies and scenery used only by that map, including enemies that only appear when another one bursts. |
| `defenders_small.png` | 1x1 defenders. |
| `defenders_medium.png` | 2x2 defenders. |
| `defenders_large.png` | 3x3 defenders. |
| `shared.png` | Effects, icons, default scenery, and anything used on more than one map. |

The script works this out from `content.json`, so rerun it after changing which enemies or scenery a map uses. Otherwise a sprite can end up on the wrong sheet, though the game still finds it.

## How it works
**Threads:** all game and UI state belongs to the Swing EDT, where one timer steps the engine and repaints. The timer runs every 33 ms while the panel is showing and every 100 ms while a match runs hidden, and it stops when there's nothing to do. RuneLite events arrive on the client thread and reach the panel through `SwingUtilities.invokeLater`. `Progression` is immutable so it can be passed between the two.

**XP:** only XP gained after a per-session baseline counts. The baseline is reset on logout, world hop, lost connection and profile change, and is retaken on the next game tick, so a character's existing XP is never credited.

**Saves:** saves go through `ConfigManager` in the `runedefence` config group, stored against the RuneScape profile so characters stay separate. The keys are `eligibleXp`, `records` and `match`. Before the first login, saves are held in memory only.

**XP rate:** only OSRS XP is stored. RuneDefence XP and level are derived from it using the `xpRate` setting, which is shared by all characters. That makes changing the rate reversible, and it needs no save migration. `Progression` clamps the rate to 1 to 10, because a hand-edited profile could otherwise divide by zero.

**Level changes:** lowering the level is safe mid-match, because the engine only checks level when placing a new defender or starting a new match.

**Binding:** a bound enemy stops walking, and bosses can't be bound. A bind also locks the enemy out of being bound again for twice its duration, so nothing can be held for more than half the time, however many binders cover it. That's what makes long or area binds safe to add. Defenders with `seeksUnbound` spread their binds by preferring enemies that can still be held, but they keep attacking when none can.

**Attack speed:** the data stores attacks per second, so a bigger number is faster. Players are always shown seconds between attacks, from `GameEngine.attackInterval`, which is the same value the simulation uses.

## Changing content
- Saved matches only restore if their content version matches `version` in `content.json`. Bumping it discards players' saved matches, though not their XP or records.
- `ContentValidator` checks `content.json` at startup. If it fails, the sidebar shows an error instead of the game.
- After changing late waves, check the result with `./gradlew balanceReport`.

## Plugin Hub rules
Read `AGENTS.md` before adding features. It covers the coding standards and the features RuneLite and Jagex don't allow.

Don't rename a config key or group without a migration, because that silently resets players' settings. Saves use the same group.

## Releasing
`runelite-plugin.properties` uses `build=standard`, so the hub replaces `build.gradle` and `settings.gradle` with its own. Custom Gradle tasks only exist locally, and new third-party dependencies aren't possible without changing the build type.

1. Bump `version` in `runelite-plugin.properties`.
2. Test in-game, then commit and push to the public repository.
3. In your fork of [runelite/plugin-hub](https://github.com/runelite/plugin-hub), update `plugins/runedefence` with the `repository=` clone URL and the full 40-character `commit=` hash. For an update, only `commit=` changes.
4. Open a pull request, and add this footer to its description:

   ```
   Generated-by: Claude Code
   ```
